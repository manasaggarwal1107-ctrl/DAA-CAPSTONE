# Benchmark Results

## 1. Experimental Environment

All measurements in this document were generated by the benchmark script:

`.\.venv\Scripts\python.exe scripts\run_benchmark.py --repeats 5 --seed 42`

- Generated: 24 November 2026, 09:11:24
- Operating system: Windows 11
- Python: 3.13.7
- Processor: Intel64 Family 6 Model 154 Stepping 3, GenuineIntel
- Dataset seed: 42
- Input sizes: 10, 50, 100, 500, 1,000 and 5,000 parcels

The benchmark uses `time.perf_counter()` for timing. Median runtime is reported, alongside minimum and mean values in the raw CSV/JSON files.

Five repetitions were performed for sizes up to 500 parcels. Three repetitions were performed for 1,000 and 5,000 parcels. Peak memory was measured separately using `tracemalloc`, so memory tracing does not affect the recorded timing runs.

## 2. Dataset Generation Rules

| Parameter | Rule |
|---|---|
| Parcel counts | 10, 50, 100, 500, 1,000, 5,000 |
| Random seed | 42 |
| Locations | min(max(8, n/10), 150) |
| Road network | Connected synthetic graph |
| Vehicle capacity | 25% of total parcel weight, capped at 600 kg |
| Delivery stops | Distinct destinations of selected parcels |

These are controlled synthetic datasets, not measurements from a live courier company's operational records. The road network is generated for algorithmic testing and does not represent verified real-world road distances.

## 5. Theoretical Complexity and Observed Behaviour

| Algorithm | Theoretical complexity | Interpretation |
|---|---|---|
| Merge Sort | O(n log n) | Runtime increases as parcel count grows. From 500 to 5,000 parcels, the input increases 10 times and median runtime increases approximately 12.5 times. |
| 0/1 Knapsack DP | O(nW) time | Runtime is related to the number of parcel-capacity DP cells. The 100-parcel case has 36,900 cells; the 5,000-parcel case has 3,005,000 cells. |
| Dijkstra with binary min-heap | O((V+E) log V) | Runtime depends on graph vertices and edges, rather than directly on parcel count. |
| Nearest Neighbour routing | k Dijkstra runs plus O(k²) candidate scanning | Runtime depends on both graph size and the number of distinct delivery stops. |

The observed measurements are consistent with the expected growth patterns, but they are empirical observations from this particular machine and dataset generator. They do not prove theoretical complexity.

## 6. Resource Limits and Implementation Notes

- The Knapsack implementation uses a one-dimensional DP value array and a decision structure for reconstruction.
- The decision structure uses one byte per parcel-capacity cell.
- Vehicle capacity is capped at 600 kg in this benchmark.
- The implementation has a maximum DP-cell guard of 60,000,000 cells.
- The application avoids displaying very large DP tables in the browser.
- Nearest Neighbour is a heuristic; it does not guarantee an optimal travelling-salesperson route.
- Runtime can vary with processor load and other system conditions.
